## 🧭 背景

- 小型 DC モーターの 3D 展開図を表示するサイトを，GitHub Pages で公開する．
- 部品は大きめに表示し，タップやマウスオーバーで解説を表示する．
- 対象は 130 型相当のブラシ付きモーターとし，特定の製品は再現しない．

## ✅ 判断

### 技術構成

- Vite・TypeScript・Three.js で静的サイトを構成する．
- テストは Vitest，lint と整形は Biome，E2E は Playwright と axe-core を使う．
- CSS は素の CSS とする．画面が 1 つで，部品の種類も少ないためである．

### 3D 形状

- 外部のモデルファイルを使わず，寸法の定数から形状を生成する．
- 断面の点列を純粋な関数で計算し，Three.js の押し出しで立体にする．
- 寸法を `src/motor/dimensions.ts` へ集め，配置を `src/motor/layout.ts` へ分ける．

### 展開の表現

- 回転子（シャフト・鉄心・巻線・整流子）は展開しても動かさない．
  実物でも一体であり，基準として置くと前後の部品の位置関係を読み取りやすい．
- 永久磁石は軸と直交する方向へ離し，回転子を挟む関係を示す．
- 縦長の画面では，モデル全体を回して軸を縦へ向ける．
- 展開度が変わるたびに，全体が収まる距離へカメラを置き直す．

### 解説の表示

- マウスではホバーでポインターの近くへ吹き出しを表示する．
- タップ・クリック・キーボードでは，画面の決まった位置へ固定して表示する．
- 番号のラベルを HTML のボタンとし，3D の位置へ重ねる．
  キーボードと支援技術から操作できる入口を兼ねる．

### 公開

- `main` への push で GitHub Actions からビルドし，Pages へ公開する．
- 出力のパスは相対（`base: "./"`）とし，リポジトリ名の変更に影響されないようにする．
- OGP の画像と URL だけは絶対 URL が必要なため，`index.html` に直接書く．

## 🚫 代替案と棄却理由

表 1. 検討した代替案と棄却理由

| 代替案 | 棄却理由 |
|---|---|
| glTF などのモデルファイルを読み込む | モデルの作成手段がなく，寸法の変更もテストもしにくい |
| React Three Fiber などの UI フレームワーク | 画面が 1 つで状態も少なく，依存を増やす利点が小さい |
| 注目していない部品を半透明にする強調 | 重なった半透明の面で描画順の乱れが起きやすい．発光色による強調で足りる |
| フォーカス可能な canvas でキー操作を受ける | 非対話的な役割の要素へフォーカスを置くことになる．文書全体でキーを受ける方式にした |
| `gh-pages` ブランチへの公開 | ビルド成果物を履歴へ残すことになる．Actions からの公開のほうが権限も絞れる |

## 🐞 実装中に得た知見

- 電機子の外径がケースの平面部へ干渉する寸法を，組立状態のテストが検出した．
  断面が円でないケースでは，半径だけでなく平面までの距離とも比較する必要がある．
- 負の移動量へ 0 を掛けると `-0` になり，`toEqual` が `0` と区別して失敗する．
  計算結果へ 0 を足して `0` へそろえた．
- マウスを重ねたままでは，選択を解除してもホバーによる解説が残った．
  解除とホバーの解消を同時に行うようにした．`Esc` キーではどちらも閉じる．
- GPU のない環境の Chromium では，WebGL に `--enable-unsafe-swiftshader` が必要である．
  ソフトウェア描画は初期化に 2 秒ほどかかるため，アニメーションの検証は待ち時間を延ばした．
- `actions/configure-pages` は使わない．
  相対パスで出力するため基準パスの取得が不要で，ビルド側の権限を `contents: read` に保てる．
