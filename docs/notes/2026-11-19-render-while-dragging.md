# 🖐️ ドラッグ中に表示が更新されない不具合の修正

視点をドラッグしても表示が変わらず，指を離したときにだけ変わる不具合を直した記録である．
原因，再現の方法，修正の内容，見落としていた理由を扱う．

## 🧭 背景

- 利用者から，表示が滑らかに動かないと報告があった．
- 当初は GPU での描画の重さを疑い，切り分け用の設定を加えた．
- その後，ドラッグ中は表示が変わらず，指を離すと変わるという報告があった．
- これは描画の重さではなく，描画が行われていない症状である．

## 🔍 原因

本サイトは，表示が変わったときだけ描画する．
描画するかどうかは，描画ループで呼ぶ `controls.update()` の戻り値で決めていた．

OrbitControls は，ポインターやホイールの入力を処理する中でも `update()` を呼ぶ．
視点の変化はその時点で適用され，描画ループでの `update()` は「変化なし」を返す．
このため，入力による視点の変化が描画へ伝わらなかった．

症状が出る条件は次のとおりである．

- OS の「動きを減らす」設定が有効である．この設定では視点の減衰を切っている．
- 減衰が有効なら，描画ループでの `update()` が残りの動きを進めるため描画される．
- 指を離すと `pointerleave` で強調表示を更新し，その描画で視点の変化が現れる．

マウスのドラッグでは，吹き出しを閉じる処理が毎回描画を求めていた．
この副作用が不具合を隠していた．ホイールでの拡大にも同じ不具合があった．

## ✅ 判断

- OrbitControls の `change` の通知を受けたときに，描画を求めるようにした．
- 描画ループでの `update()` は，減衰の動きを進めるためだけに呼ぶ．
- 再現するテストを先に書き，修正の前に失敗することを確かめた．
- 指での操作は，Chromium の DevTools Protocol で押下と移動を個別に送って確かめる．
- ホイールでの拡大は，マウスを動かさずに表示が変わることを 3 つのエンジンで確かめる．

表 1. 検討した代替案と棄却理由

| 代替案 | 棄却理由 |
|---|---|
| ポインターの移動のたびに描画を求める | ホイールやキー操作など，入力の種類ごとに同じ対応が要る．取りこぼしが残る |
| 常に毎フレーム描画する | 静止中も GPU を使い続ける．スマートフォンでの電池の消費が増える |
| 「動きを減らす」設定でも減衰を有効にする | 利用者の設定に反する．原因も残る |

## 🐞 実装中に得た知見

- 既存の E2E テストは「動きを減らす」設定で動かしていたが，マウスでしか操作していなかった．
  マウスでは別の処理が描画を求めるため，不具合を検出できなかった．
- 縦長の画面では軸が縦を向く．横になぞるだけでは，軸上の番号ラベルが動かない．
  指での操作のテストでは，斜めになぞって縦の回転も加えた．
- 症状の報告から原因を推測するときは，重さと未描画を区別して確かめる必要がある．
  最初に，「遅い」のか「変わらない」のかを利用者へ確かめるべきだった．
